# AGENTS.md

Project-specific instructions for coding agents working in this repo.

## Project overview
Load, PV, and battery analysis pipeline for interval electricity load data. Steps: clean/aggregate -> EDA -> TOU classification/costing -> grid + PV + battery + load simulation with SOC limits, a programmable battery controller, and bill/savings estimates.

The PV optimal-capacity binary search was removed. Step 4 evaluates only the capacities listed in `solar_pv.install_capacities_kwp` and reports each case independently. The current config evaluates `100` and `500 kWp`.

## Tech stack
- Python 3.10
- pandas, numpy, matplotlib, seaborn
- pvlib (used only by `solar_profile.py`)
- requests
- unittest for `tests/`
- Windows/PowerShell environment

## Pipeline (must run in order)
```bash
python 1_data_cleansing_aggregate.py
python 2_exploratory_data_analysis.py
python 3_load_clascify.py
python 4_load_pv_batt.py
```

All intermediates go to `temporary/`. Results go to `result_<year>/` created from the first timestamp's year.

## Key conventions & gotchas
- **Hardcoded paths**: Step 1 reads `source/iwrm/EnergyDayChartAll2022_edit.csv`. Update for other datasets.
- **Year detection**: Result folder name and the required `solar_1kW_<year>.csv` both come from the first load timestamp's year.
- **Solar input is required**: Step 4 reads `solar_1kW_<year>.csv` directly from the repo root. There is no NASA/clearsky fallback; a missing file raises `FileNotFoundError`. `solar_profile.py` is standalone, not imported by step 4.
- **Config is the source of truth (step 4)**: required sections are `solar_pv`, `grid`, `battery`, `tariff`, and `analysis`. Edit config instead of hardcoding constants. There is no `optimizer` section anymore.
- **Battery capacity**: `battery.capacity_kwh: null` uses the configured percentile (`battery.sizing_percentile`, default 60) of daily PV surplus before battery charging/export. A fixed capacity applies to every PV case. With the current `100/500 kWp` cases the heuristic sizes the battery per case, so results are not directly comparable by one fixed capacity.
- **Battery limits**: `power_limit_kw` is required when the battery is enabled. `charge_power_kw`/`discharge_power_kw` can override it; current config uses `20 kW` for both. SOC is bounded by `capacity_kwh * (1 - depth_of_discharge)` and `capacity_kwh`. Charge/discharge efficiencies are active. Initial SOC is `initial_soc_percent`.
- **Battery controller**: `battery.controller.name` is `self_consumption`, `schedule`, or `custom`. Schedule rules use `days`, `start`/`end` (end-exclusive), `action`, `source`, `power_kw`, `target_soc_percent`, `allow_export`, and `enabled`; the last matching rule wins. Current config uses `schedule` with `default_action: idle`: weekdays discharge `18:00-21:00` to `20%` SOC and charge from PV `10:00-14:00` to `90%` SOC; unmatched hours do nothing. The simulator enforces SOC/power/efficiency/grid limits after controller commands.
- **Grid charging**: `battery.allow_grid_charge` defaults to `false`; controller rules requesting `source: "grid"` are ignored unless it is enabled.
- **Grid sign and export**: positive grid flow = import, negative = export. `grid.allow_export` and `grid.export_limit_kw` control export. `tariff.export_thb_per_kwh` is currently `0`.
- **Bill**: system bill = grid import cost + demand charge on peak grid import + service charge - export credit. Baseline uses load only. FT and VAT are excluded.
- **Solar profile format**: `timestamp,pv` with timestamps in `%d/%m/%Y %H:%M`. `solar_1kW_2022.csv` and `solar_1kW_2023.csv` are identical (typical-year profile). Tracking files exist; set `solar_pv.use_tracking` in `config.json` to switch to `solar_1kW_<year>_tracking.csv`.
- **PV adjustment factor**: `solar_pv.install_capacities_kwp` and `pvsyst_yield_kwh_per_kwp_year` are paired lists and must have equal length. Each factor is `PVSyst yield / reference_yield`; a capacity not found in the list falls back to the mean factor (~1.0878). This is not an optimizer.
- **`temporary/` must already exist**: Step 4 no longer creates `temporary/`; run steps 1-3 first.
- **Per-capacity outputs**: `temporary/load_pv_profile_<capacity>kWp.csv` is written for each configured capacity; the current config produces `load_pv_profile_100kWp.csv` and `load_pv_profile_500kWp.csv`. `temporary/load_pv_profile.csv` is overwritten by the last capacity and should not be used for comparisons.
- **Average profiles**: `average_load_pv_profile_<capacity>kWp.csv` is written only for configured capacities. Step 4 does not delete outputs for capacities that are no longer configured, so check filenames against the current config and do not assume every `average_load_pv_profile_*.csv` belongs to the latest run.
- **Dispatch outputs**: `system_performance_dispatch_<capacity>kWp.csv` mirrors the core REopt dispatch columns (load, grid/PV/battery serving load, charging, export, curtailment, SOC). `system_dispatch_<capacity>kWp_<month>_<Month>.png` shows monthly stacked dispatch in kW with SOC on a 0-100% secondary axis. The root `REopt System Performance Dispatch.csv` is a reference sample only and is not read by the pipeline.
- **Holidays**: Step 4 reads `tariff.holidays` from `config.json` (2021-2024). Step 3 still has its own hardcoded PEA holiday list; update both for other years.
- **Tariffs**: Default Roland (5.5 THB/kWh on/off peak, 74.14 THB/kW demand, 312.24 THB/month). Alternatives commented for >69kV/22-33kV.
- **Plots**: Some plots use `plt.show()` (blocked in non-interactive). Set `MPLBACKEND=Agg` for headless runs.
- **Windows paths**: Scripts use Windows-style paths; run from repo root.
- **Git**: `temporary/`, `solar_cache/`, `.venv/` are ignored. `result_2022/` is tracked and currently dirty; changing `solar_pv.install_capacities_kwp` and rerunning can replace tracked outputs with new capacity-specific files. Review `git status` and don't commit generated changes unless asked.

## Commands
```powershell
# Setup (Python 3.10). Use the venv: the global interpreter lacks the dependencies.
py -3.10 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
$env:MPLBACKEND = "Agg"  # optional headless

# Run pipeline (venv active)
python 1_data_cleansing_aggregate.py
python 2_exploratory_data_analysis.py
python 3_load_clascify.py
python 4_load_pv_batt.py

# Tests
python -m unittest discover -s tests -t . -v

# Syntax check
python -m py_compile 1_data_cleansing_aggregate.py 2_exploratory_data_analysis.py 3_load_clascify.py 4_load_pv_batt.py energy_system.py battery_controllers.py custom_battery_controller.py solar_profile.py PVGIS_TMY.py
```

## Editing guidelines
- Keep existing code style (minimal comments). Don't add emoji/comments unless requested.
- When changing paths/assumptions (year, tariffs, holidays), update `config.json` and any affected scripts consistently.
- Do not reintroduce the optimal-capacity binary search or `optimizer` config unless explicitly requested.
- If changing battery behavior, update `energy_system.py`, the relevant controller, tests, and both `README.md` and `AGENTS.md`.
- Treat `solar_pattern.csv` and `result_2022/` changes as generated unless the user asks.
- Don't commit generated files (`temporary/`, `solar_cache/`, `.venv/`).
